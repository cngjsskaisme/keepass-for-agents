# 릴리스 체크리스트

이 문서는 처음 사용하는 사람이 아닌 **유지보수·배포 담당자**를 위한 체크리스트입니다. 실행하지 못한 테스트도 근거를 남겨야 합니다.

## 1. 배포 준비

- [ ] `package.json` 버전을 업데이트하고 지원 Node.js 버전(22.18 이상 또는 23.6 이상)을 확인합니다.
- [ ] 한국어·영어 문서의 기능 설명이 실제 코드와 일치하는지 확인합니다.
- [ ] 사용자에게 영향을 주는 변경 사항과 설정 업데이트 주의사항을 릴리스 노트에 기록합니다.
- [ ] `config.toml` 형식과 에이전트 권한 변경을 검토합니다.

## 2. 품질 검사

```sh
npm ci
npm run typecheck
npm test
npm run lint:py
npm run docs:build
```

- [ ] Windows와 Linux에서 Node.js 22.18·24 CI가 통과했습니다.
- [ ] 깨끗한 Python 환경에 필요한 패키지를 설치할 수 있습니다.
- [ ] 실패하거나 건너뛴 필수 테스트를 설명 없이 방치하지 않았습니다.

::: warning 실행하지 않은 테스트는 통과가 아닙니다
실제 KeePass/KPScript 연동, 별도 OS 계정 검증 또는 지원 플랫폼 테스트를 수행하지 못했다면 **NOT_VERIFIED**로 표시하세요. Mock 테스트만으로 운영 가능하다고 판단하면 안 됩니다.
:::

## 3. 설치와 복구 확인

- [ ] Windows·Linux 설치 미리보기 결과가 예상과 일치합니다.
- [ ] 새 환경에서 `kp doctor`가 필요한 조치와 진단 결과를 안내합니다.
- [ ] 설정 파일 마이그레이션 후 기존 정책이 유지됩니다.
- [ ] Hardened Mode를 지원 환경에서 설정·검증·복구할 수 있습니다.
- [ ] 업데이트·제거 과정에서 기존 KDBX 파일이 보존됩니다.

## 4. 배포 파일 검사

```sh
npm run verify:artifact
npm pack --dry-run
```

- [ ] GPL 라이선스의 KeePass/KPScript 실행 파일이 포함되지 않았습니다.
- [ ] KDBX 파일, 개인 키, 로그, `.env`, `node_modules`, 테스트 임시 파일이 포함되지 않았습니다.
- [ ] 필요한 실행 스크립트, 문서, 라이선스 파일이 포함됐습니다.

## 5. 보안 확인

- [ ] 일반 CLI/MCP 응답으로 비밀번호 원문이 전달되지 않습니다.
- [ ] 워커 허용 목록, 접속 대상 검사, 에이전트 접근 권한이 유지됩니다.
- [ ] Hardened Mode는 격리 조건을 충족하지 못하면 작업을 거부합니다.
- [ ] `KEEPASS_AGENT_SERVICE_SELFTEST` 같은 테스트 전용 설정을 운영용으로 안내하지 않습니다.
- [ ] 남은 보안 한계를 [보안 모델](/ko/security)에 기록했습니다.

## 6. 배포

- [ ] 배포 커밋의 필수 리뷰와 CI가 통과했습니다.
- [ ] 검토된 버전에 `vX.Y.Z` 태그를 생성했습니다.
- [ ] 검증된 배포 파일을 배포 방식에 따라 첨부하거나 게시했습니다.
- [ ] [설치](/ko/installation), [운영 가이드](/ko/operations), 릴리스 노트를 연결했습니다.
