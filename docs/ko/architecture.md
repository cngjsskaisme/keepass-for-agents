# 아키텍처

keepass-agent의 역할은 단순합니다. **허용된 인증 요청을 받아 실행 결과만 돌려주고**, 비밀번호 처리는 신뢰된 구성요소에서 수행합니다.

## 요청 처리 흐름

```text
                     AI 에이전트
                          │
                      CLI / MCP
                          │
                    권한 검사·감사
                          │
             ┌────────────┴────────────┐
             ▼                         ▼
        Standard Mode              Hardened Mode
          로컬 실행                  인증된 IPC
             │                         │
             │                Credential Service
             │                  (별도 OS 계정)
             └────────────┬────────────┘
                          │
                KeePass 접근 모듈 (KDBX)
                          │
                    승인된 로그인 워커
                          │
                      정제된 결과
```

**Standard Mode**는 호출한 에이전트와 같은 OS 사용자 권한에서 실행됩니다. **Hardened Mode**는 인증 작업을 별도로 설정한 서비스에 전달합니다. 기본 CLI/MCP 인터페이스는 두 모드에서 동일합니다.

## 주요 구성요소

| 구성요소 | 역할 |
| --- | --- |
| CLI / MCP | 요청을 받고 구조화된 결과 반환 |
| 권한 정책·감사 기록 | 허용된 에이전트 작업·계정·사이트 검사 및 기록 |
| KeePass 접근 모듈 | Windows의 KPScript, Linux의 PyKeePass 연동 |
| Credential Service | Hardened Mode에서 세션과 인증정보를 별도 프로세스로 관리 |
| 로그인 워커 | 허용된 로그인 작업 실행. 비밀번호 원문은 반환하지 않음 |
| 로컬 승인 화면 | 브라우저에서 저장소 잠금 해제 및 필요한 작업 승인 |

## 예시: 웹사이트 로그인

1. 에이전트가 특정 계정으로 로그인을 요청합니다.
2. 게이트웨이가 에이전트 권한과 대상 사이트를 확인합니다.
3. 신뢰된 구성요소가 KeePass 저장소에서 해당 계정 정보를 읽습니다.
4. 승인된 워커가 표준 입력(stdin)으로 전달받은 인증정보를 사용해 로그인합니다.
5. 에이전트에는 **비밀번호가 아닌 실행 결과**만 반환됩니다.

브라우저 로그인은 운영자가 설정한 로컬 CDP 브라우저로 수행하며 기본적으로 격리된 브라우저 환경을 사용합니다. 자세한 한계는 [보안 모델](/ko/security)을 참고하세요.

## Windows와 Linux의 차이

- **Windows:** 인증정보 조회에 KeePass 2.x·KPScript, 계정 생성·수정에 PyKeePass 사용
- **Linux:** Python 3.10 이상·PyKeePass 사용
- **Hardened Mode:** 두 운영체제 모두 별도 서비스 계정과 파일 권한 설정이 필요하며 자동 활성화되지 않음
