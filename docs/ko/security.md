# 보안과 한계

keepass-agent는 AI 에이전트가 **비밀번호 원문을 받지 않고도 승인된 로그인 작업을 요청**하도록 돕습니다. 하지만 OS 파일 권한을 대신하거나 모든 인증정보 탈취를 막는 제품은 아닙니다.

## 보안 모드 비교

| | Standard Mode (기본) | Hardened Mode (선택) |
| --- | --- | --- |
| 에이전트 도구 응답 | 비밀번호 원문 제외 | 비밀번호 원문 제외 |
| KeePass 저장소 접근 | 에이전트와 같은 OS 사용자 권한 | 별도 Credential Service 계정 |
| 파일·세션 격리 | **같은 사용자 프로세스와 격리되지 않음** | 올바르게 설정했다면 OS 권한으로 분리 |
| 준비 과정 | 기본 설치 | 서비스 계정·파일 권한·IPC 추가 설정 |
| 서비스 장애 시 | 해당 없음 | **작업 거부**. 일반 모드로 자동 전환하지 않음 |

::: danger Standard Mode는 프로세스 격리를 제공하지 않습니다
**같은 OS 사용자 권한**으로 실행되는 악성 프로그램은 도구를 거치지 않고 KeePass 파일이나 세션 정보에 접근할 수 있습니다. 에이전트 자체를 신뢰할 수 없다면 별도로 구성한 Hardened Mode를 검토하세요.
:::

## 무엇을 보호하나요?

- **도구 응답:** 계정 검색은 이름·주소 등의 정보만 반환합니다. 로그인 결과에도 비밀번호 원문은 포함하지 않습니다.
- **잠금 해제:** 사용자는 AI 채팅창이 아닌 로컬 브라우저 승인 페이지에 마스터 비밀번호를 입력합니다.
- **로그인 대상:** 계정에 저장된 주소를 검사하고 다른 사이트로 인증정보를 전송하는 시도를 제한합니다.
- **접근 권한:** 에이전트별로 허용 작업·계정·사이트를 제한할 수 있습니다.
- **감사 기록:** 작업과 결과는 기록하지만 비밀번호나 쿠키 값은 기록하지 않도록 설계돼 있습니다.

승인된 로그인 워커에는 표준 입력(stdin)으로 인증정보가 전달됩니다. 출력 필터는 보조 안전장치일 뿐, **인코딩하거나 변형한 모든 비밀번호까지 완벽하게 제거한다고 보장할 수는 없습니다.**

## 반드시 알아야 할 한계

| 한계 | 의미 |
| --- | --- |
| 초기 권한이 광범위함 | 현재 `config init`은 `default` 에이전트에 `allowed = ["*"]`를 부여합니다. AI 연결 전에 줄여야 합니다. |
| 에이전트 이름은 자기 선언 | `--agent`, 환경변수, MCP 클라이언트 이름만으로 호출자 신원을 증명하지 못합니다. |
| 브라우저 승인이 사람이라는 증거는 아님 | 승인 URL을 얻은 로컬 프로세스도 페이지를 조작할 수 있습니다. 별도의 본인 확인 수단으로 간주하면 안 됩니다. |
| 세션 쿠키도 중요한 인증정보 | 쿠키 수집에는 승인이 필요하지만, 저장된 세션 자체가 계정 접근 권한을 가질 수 있습니다. |
| 로그인 성공 판정에는 한계가 있음 | URL 변화나 화면 표시만으로 로그인 성공을 확정할 수 없습니다. |
| OS 호출자 신원 확인에 미구현 부분이 있음 | 플랫폼별 커널 수준 호출자 확인은 아직 완전히 구현되지 않았습니다. |
| 메모리 완전 삭제는 보장하지 않음 | JavaScript 실행 환경에서는 평문 정보가 메모리에서 즉시 제거된다고 보장할 수 없습니다. |

::: warning 실제 계정을 사용하기 전에
OS 계정 분리가 적용됐는지, 에이전트 권한과 브라우저 연결 주소가 적절한지, 사용자가 어떤 방식으로 승인하는지 확인하세요. KDBX 파일은 별도로 백업하세요.
:::

## 인증정보가 처리되는 흐름

```text
AI 에이전트 → CLI / MCP → 접근 권한 검사
                             │
             ┌───────────────┴──────────────┐
             │ Standard Mode                │ Hardened Mode
             ▼                              ▼
        로컬 인증 처리                 인증된 IPC 통신
             │                              │
       KeePass 접근 모듈             별도 Credential Service
             │                              │
             └──────── 승인된 워커 ─────────┘
                              │
                         정제된 결과만 반환
```

**Hardened Mode**는 저장소 접근, 세션, 로그인 워커를 별도 OS 계정에서 실행합니다. 토큰 파일과 KDBX 권한을 검사하며 격리 조건을 만족하지 않으면 작업을 거부합니다.

활성화 전 [운영 가이드](/ko/operations)를 읽고 에이전트 계정으로 `kp status`와 `kp doctor` 결과를 확인하세요.

## 상세 기술 자료

HMAC/IPC 인증, Windows·Linux 파일 권한, CDP 검증, 감사 기록과 미구현 항목은 [보안 구현 상세](/ko/security-internals)에서 확인할 수 있습니다.

단순한 권한 설정이 목적이라면 [설정과 접근 권한](/ko/configuration)부터 보세요.
